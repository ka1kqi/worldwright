Worldwright

An LLM/VLM agent that autonomously authors simulation tasks in Genesis World 1.0 — a modern reimplementation of RoboGen built on the new genesis physics stack.

Design v0.0.1 · Phase A complete · Targets Apple M2 (Metal) first, cloud NVIDIA later.

Goal Architecture Engine wrapper Agents Self-correction loop Data schema Metrics Repo skeleton Milestones Risks

1. Goal

Given a domain seed (e.g. “Franka tabletop block manipulation”), Worldwright autonomously:

  1. proposes a concrete task,
  2. generates the scene as Python code that drives our thin Genesis wrapper,
  3. synthesises a success/reward predicate as code,
  4. runs the scene in Genesis World 1.0 and executes a scripted oracle to test solvability,
  5. self-corrects failures (scene-build error, IK infeasible, oracle didn’t reach success),
  6. logs validated tasks and trajectories as a training-ready LeRobot dataset.

The result is both a portfolio artifact (an end-to-end agentic dataset generator) and a runnable benchmark for downstream policy training.

3. The engine wrapper

The wrapper is the project’s most important design surface: it’s simultaneously (a) the only place we touch Genesis, (b) the API the LLM sees as “the world”, (c) the type contract verifiers and dataset writers consume. Wrapping rather than scattering genesis calls through agent code gives us one chokepoint when the 1.0 API moves.

3.1 Surface sketch

class WorldwrightScene:

    def get_quat(self) -> np.ndarray: ...

@dataclass(frozen=True)
class SceneState:
    t: float
    franka_q: np.ndarray; franka_qdot: np.ndarray
    ee_pos: np.ndarray; ee_quat: np.ndarray
    objects: dict[str, ObjectState]   # name -> pos, quat, vel
    contacts: list[ContactInfo]

3.2 Why this shape

  • Names instead of indices. Genesis returns DoF indices; we surface joint names and skill-level verbs (open_gripper()) so the LLM can’t mis-index.
  • One step per scene.step(). No hidden loops → Verifier can attribute every observation to a precise simulation step.
  • State is a snapshot dataclass, not a live handle. Success predicates close over a frozen SceneState, so they’re trivially testable in isolation without rebooting the sim.
  • Numpy at the boundary. The wrapper converts MPS / CUDA tensors to host numpy at the API edge; agents never see device-laden tensors. (Discovered the hard way during vertical-slice reproduction.)
  • Renderer is optional and lazy. Vertical slice runs without rendering. Nyx vs. Pyrender is a constructor flag, not a leak through the API.

4. Agents

4.1 Model assignment

AgentModelWhy
Proposerclaude-sonnet-4-6Cheap, fast, English-out; creativity matters more than rigor.
SceneCoderclaude-sonnet-4-6Calling a small typed API — well within Sonnet’s coding band.
RewardCoderclaude-opus-4-7Hardest reasoning step; subtle off-by-one in a success predicate poisons the whole dataset. Worth the spend.
Criticclaude-sonnet-4-6Pattern-matching from logs to patches. Promoted to Opus if first-pass diagnosis fails on a tracked benchmark.

4.2 Structured outputs

All four agents use Anthropic tool_use-style structured output, schemas defined as pydantic.BaseModel in worldwright.task. Code emissions are returned as a single scene_code: str / success_code: str field; both are then run through ast.parse + a forbidden-name visitor before exec.

4.3 Per-task token budget

Default: 30 K input + 4 K output per agent call, 4 critic iterations max ⇒ ceiling ≈ (3 + 4) authoring calls + 4 critic calls = 11 calls / task. Rough cost model used for M2 / M3 planning, surfaced in run logs.

5. The self-correction loop

  1. Seed in. Pipeline picks a seed (free text + RNG salt).
  2. Propose. Proposer returns TaskSpec: description, object list, intent (“lift cube onto target zone”), invariants.
  3. Code scene. SceneCoder returns build_scene(s: WorldwrightScene). Run AST + sandbox checks; dry-build the scene (catch geometric / asset errors before stepping). On failure → Critic with the traceback → patch.
  4. Code reward + oracle hint. RewardCoder returns success(state) -> bool and an OracleHint (target objects, grasp pose, sequence). Static-check + unit-call against the scene’s initial SceneState (must not crash).
  5. Solve. Solver runs IK + plan_path for each oracle phase, executes the trajectory, samples SceneState per step. Records contact, success-at-step, terminal state.
  6. Verify. Verifier evaluates success(terminal_state) and produces VerifierReport with full run log + (on failure) a diagnosis hint (“IK infeasible at phase 2”, “success() never fired but oracle completed”, “cube fell off table”).
  7. Critic. If failed and budget remains, Critic returns a patch type (SCENE, SUCCESS, ORACLE) + new source. Loop back to step 3 / 4. Else mark task UNSOLVABLE.
  8. Log. Validated tasks: persisted to LeRobot dataset + raw NPZ + task manifest JSON.

7. Metrics

7.1 Validity

  • valid_rate = validated_tasks / proposed_tasks. Target ≥ 0.5 for M2.
  • first_try_success_rate = oracle pass without Critic intervention. Diagnostic for prompt quality.
  • critic_iterations_per_validated_task. Cost proxy.
  • tokens_per_validated_task (in + out, per agent). $-cost proxy.
  • solver_wallclock_s_per_task. Throughput proxy.

7.2 Diversity (for the dataset deliverable)

  • Object-count distribution, object-type entropy, size-bucket coverage.
  • Spatial-layout entropy: discretise tabletop into an 8×8 grid; measure entropy of (object → cell) occupancy across the dataset.
  • Skill taxonomy coverage: Proposer labels each task with one or more skill tags (pick, place, push, stack, insert). Report task counts per tag.
  • Reward-function clustering: embed each success_code (Voyage embeddings or Claude-as-embedder), HDBSCAN; report cluster count + silhouette.

10. Risks & de-risk plan

  1. Nyx renderer on Apple Metal is unverified. high
    Nyx ships as a separate genesis-nyx package; the Metal path isn’t documented as supported. If broken, every M3 image-observation feature stalls. De-risk M1 sprint 1: attempt Nyx init + render a single frame on M2; if it crashes, fall back to Pyrender for M1 / M2 and re-attempt Nyx only after the cloud-GPU jump.
  2. Scene build cost. de-risked this session
    Cold first build is ~50 s (Quadrants kernel compilation). Critical question was whether the fastcache persists across processes. Empirically: a fresh process picks up the cached kernel in ~3.1 s. Acceptable for the self-correction loop. Document the cache path in the wrapper.
  3. IK + plan_path is a weak proxy for solvability. med
    A task can pass geometric reachability + collision-free pathing and still be physically unsolvable (gripper geometry vs object shape, friction limits, etc.). De-risk M2 sprint 1: hand-label a 20-task validation set; measure oracle false-positive rate; if > 20 %, add a contact-stability check post-grasp (cube must remain in finger contact during lift).
  4. RewardCoder produces uncompilable / semantically wrong success functions. med
    Reward synthesis is the hardest code-gen task in the system. De-risk M1: measure pass-at-1 compile rate & pass-at-1 correctness against the hand-labeled set; if < 70 %, ablate Sonnet vs Opus and consider a chain-of-thought scratchpad.
  5. M2 throughput ceiling for dataset-scale. low
    84 step/s × ~700 steps / task × 50 tasks ≈ 7 minutes of sim per 50-task batch. Fine for M1 / M2; M3 needs cloud NVIDIA, already planned.
  6. Asset diversity without an external catalog. low
    Genesis ships 11 URDFs & 22 meshes; tabletop block manipulation is fine on primitives alone. PartNet-Mobility / Objaverse integration is M3 work, not blocking.
  7. LLM-generated code as an unintended-side-effect surface. low
    Pipeline runs locally on a dev box. The utils/sandbox.py AST guard blocks filesystem, subprocess, and network builtins / modules from M1 onward — primarily for correctness (a typo’d module name that imports the wrong thing), secondarily as defence-in-depth.
  8. Device-tensor leakage at the wrapper boundary. de-risked this session
    The vertical-slice reproduction surfaced that RigidEntity.get_pos() returns MPS tensors on Metal that can’t be passed directly to numpy. Wrapper converts to host numpy at every public getter; success predicates and dataset writers never see device tensors.
